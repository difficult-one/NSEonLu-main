# F334 超级电容 CAN 通信协议

本文档描述了 NSEonLu F407 底盘控制器与独立的 F334 超级电容控制器之间的通信约定。

2026-10-12：支持独立输入功率闭环。当前默认直供模式不注册电容CAN模块；宏切换到电容模式后使用下述扩展，F334需同步更新。[动态缓冲策略说明](superpowers/specs/2026-10-12-dynamic-buffer-energy-design.md)。

## 总线配置

- 经典 CAN，使用标准 11 位标识符。
- F407 指令帧 ID：`0x061`。
- F334 状态帧 ID：`0x051`。
- F334 输入功率反馈 ID：`0x052`。
- 三帧 DLC 均为 8。
- 多字节数值使用小端字节序。
- F407 在 `ChassisTask()` 中每 5 ms（200 Hz）发送一次指令。
- F334每5 ms（200 Hz）发送`0x051`状态和`0x052`输入反馈，避免增加反馈帧后占用过多总线带宽。
- F407 在 200 ms 内未收到有效状态帧时，判定 F334 离线。
- 新缓冲策略分别要求`0x051/0x052`不超过20 ms；输入帧不刷新负载状态看门狗。F334有效指令失联超过100 ms关闭DCDC。

## 指令帧：F407 → F334，ID 0x061

| 字节 | 格式 | 含义 |
|---:|---|---|
| 0 | 位域 | bit0：使能 DCDC；bit1：重启请求；bit2-7：置零 |
| 1-2 | `uint16_t`，小端 | 裁判系统底盘原始功率上限（W） |
| 3-4 | `uint16_t`，小端 | 裁判系统原始缓冲能量（J） |
| 5-6 | `uint16_t`，小端 | 独立输入功率目标（W），仅扩展使能时有效 |
| 7 | `uint8_t` | `0xA5`使能输入闭环扩展；关闭新策略或DCDC禁用时置零 |

正常运行时的编码始终将重启请求位置零。重启不属于周期性的底盘控制内容。

示例：使能 DCDC，功率上限 `100 W`，缓冲能量 `50 J`：

```text
01 64 00 32 00 00 00 00
```

扩展示例：原始限额80 W、缓冲60 J，独立输入目标110 W：`01 50 00 3C 00 6E 00 A5`。原始限额字段不会被110 W目标替换。

## 输入功率反馈：F334 → F407，ID 0x052

| 字节 | 格式 | 含义 |
|---:|---|---|
| 0-3 | IEEE-754 `float`，小端 | 电管实际输入功率（W），不含电容放电贡献 |
| 4-5 | `uint16_t`，小端 | 当前输入功率环目标（W） |
| 6 | `uint8_t` | 协议版本1 |
| 7 | 位域 | bit0：扩展输入控制生效；bit1-7：0 |

版本不匹配、非法浮点或错误长度不刷新输入状态。新鲜反馈且bit0有效后才放开电容模式的缓冲增量；旧F334固件仅提供`0x051`时保持基础预算。`0x051`中的实测底盘功率仍用于负载侧诊断，不能当成电管输入功率。

指令必须携带裁判系统原始功率上限；指令中绝不能携带超级电容增补后的电机功率预算。

### 裁判数据有效性

上游裁判数据遵循 2026 协议：`0x0201` 数据段固定为 13 字节，`0x0202`
数据段固定为 14 字节。缓冲能量位于 `0x0202` 数据段偏移 8（从 0
开始计数的字节 8-9），按小端 `uint16_t` 解析。

C 板只在最近 300 ms 内分别收到通过 CRC 和精确长度检查的 `0x0201`
与 `0x0202` 时，才认为裁判功率快照有效。错误帧不会覆盖仍在新鲜期内
的上次有效数据。正式配置下，快照无效（包括任一关键命令尚未收到有效
更新，或最后一次有效更新已超过 300 ms）都会令下一周期 `0x061` 变为
关闭 DCDC、功率上限 0 W、缓冲能量 0 J，即完整载荷为
`00 00 00 00 00 00 00 00`；两个命令恢复后链路自动恢复。

`CHASSIS_POWER_BENCH_TEST` 默认关闭。显式台架模式只提供配置的台架功率
上限，缓冲能量仍为 0 J，不能用于正式比赛固件。

## 状态帧：F334 → F407，ID 0x051

| 字节 | 格式 | 含义 |
|---:|---|---|
| 0 | 位域 | bit7：DCDC 输出禁用；bit0-6：错误码 |
| 1-4 | IEEE-754 `float`，小端 | 实测底盘功率（W） |
| 5-6 | `uint16_t`，小端 | F334 上报的可提供给底盘的功率（W） |
| 7 | `uint8_t` | 电容能量，`0-255` 线性映射到 `0-100%` |

状态错误码位：

| 位 | 掩码 | 含义 |
|---:|---:|---|
| 0 | `0x01` | 欠压 |
| 1 | `0x02` | 过压 |
| 2 | `0x04` | 升降压故障 |
| 3 | `0x08` | 短路 |
| 4 | `0x10` | 高温 |
| 5 | `0x20` | 无功率输入 |
| 6 | `0x40` | 电容故障 |
| 7 | `0x80` | DCDC 输出禁用 |

接收端通过按对齐要求放置的 `uint32_t` 加 `memcpy` 重组浮点数，不会把 CAN 缓冲直接强转为紧凑结构体。DLC 不为 8、或底盘功率浮点数为非有限值的帧会被拒绝，且不会刷新在线看门狗。

## 功率预算行为

### 当前动态缓冲策略（CHASSIS_BUFFER_POWER_ENABLE=1）

- 低负载保持裁判基础输入预算；只有新鲜、非制动的驱动需求超过基础目标时，才按需求缺口加 5 W 余量放开缓冲增补，仍受 60 W 输入增补上限和缓冲下限约束。
- 缓冲估算回看 96 段输入功率历史，按帧龄与结算延迟计算保守耗能；历史缺失时保留最坏扣减。估计已建立后，新读数向上校正限为 20 J/s，丢帧也不能绕过该限速，向下立即校正。
- 输入预算上升使用 600 W/s；电容模式负载预算另用 200 W/s。下降立即生效，控制步长超过 20 ms 禁止上升。
- 负载预算中的输入贡献以新鲜 `0x052` 实际目标和请求目标的较小值为准，避免把尚未确认的输入增量提前算进可用功率；`0x051` 总能力上限始终保留。
- 电容仍按原电量比例限制最多 100 W 名义负载增补，允许在缓冲恢复时继续助力。本次不增加电容容量、可用焦耳或持续时间策略，也不改变 CAN 载荷。

详见[按需求调度设计](superpowers/specs/2026-10-13-demand-aware-energy-budget-design.md)和[当前参数说明](configuration-guide.md)。

### 原预算策略（CHASSIS_BUFFER_POWER_ENABLE=0）

- 能量 ≤ 10%：不提供增补。
- 能量 10% 至 30%：增补按 0% 至 100% 线性提升。
- 能量 ≥ 30%：提供允许范围内的全部增补。
- F334 上报的增补超过裁判系统上限时，封顶为 100 W。
- 预算降低立即生效；升高限制为 200 W/s。
- 现有电机功率模型安全系数保持 0.95。

F334 离线、禁用、能量过低或故障时：立即移除超级电容增补，仅保留有效的裁判系统/台架基础预算。

电容状态不会直接调用 `DJIMotorStop()`。底盘停机行为仍由机器人急停、裁判系统发射/输出权限以及电机离线逻辑负责。
