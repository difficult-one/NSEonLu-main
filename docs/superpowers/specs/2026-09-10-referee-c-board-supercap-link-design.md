# 裁判系统—C 板—超级电容链路完善设计

## 目标

在不改动现有 C 板与超级电容 CAN 帧格式的前提下，完善裁判系统功率数据从 UART 进入 C 板、再由 C 板通过 CAN 下发给超级电容的链路。

完成后的链路必须满足：

- 正确解析 RoboMaster 2026 高校系列赛通信协议中的 `0x0201` 和 `0x0202`；
- UART 数据被拆包、合包或夹杂坏帧时能够继续同步；
- 只有通过帧头 CRC8、整帧 CRC16 和载荷长度检查的数据才能更新功率状态；
- 裁判系统关键数据无效或超时后，C 板关闭 DCDC 请求并停止沿用旧数据；
- 现有 `0x061` 指令帧和 `0x051` 状态帧保持不变；
- 功率链路核心逻辑能够在主机上自动测试，并在最后通过固件构建和上板联调验证。

## 范围

本次修改包括：

- UART BSP 向裁判模块提供本次实际接收字节数；
- 裁判系统字节流拆帧、校验、重同步；
- `0x0201` 机器人性能体系数据和 `0x0202` 底盘缓冲能量及枪口热量数据的 2026 协议定义；
- 功率数据的独立有效性、更新时间和原子快照接口；
- 底盘任务根据快照生成超级电容指令及底盘功率预算输入；
- 对以上纯逻辑的主机测试；
- 相关协议文档更新。

本次不包括：

- 修改 C 板与超级电容之间已经完成的 CAN 标识符或 8 字节载荷布局；
- 重写超级电容固件；
- 全量迁移与功率链路无关的裁判系统命令；
- 重构 UI 或机器人间交互功能；
- 修改用户正在使用的超级电容接收诊断计数。

## 协议基线

以《RoboMaster 2026 University Series Communication Protocol V1.3.0（2026-03-27）》为基线：

- `0x0201` 数据段长度为 13 字节，固定 10 Hz；
- `0x0202` 数据段长度为 14 字节，固定 10 Hz；
- `0x0201` 中的 `chassis_power_limit` 和 `power_management_chassis_output` 提供底盘功率上限与输出允许位；
- `0x0202` 的 `buffer_energy` 位于数据段字节偏移 8，单位为 J；
- 帧头中的数据段长度是 2 字节小端数值，不能只读取低字节。

仓库现有 `0x0202` 定义为 16 字节。本次将其修正为 14 字节，并移除末尾已不存在的第二个 17 mm 枪管热量字段；前三个历史字段保留其现有布局，但标记为保留字段，以保持 `buffer_energy` 的字节偏移为 8。

## 方案选择

### 采用：聚焦功率链路的可靠化

只更新功率链路依赖的协议、解析、状态和调用点，保留现有模块组织及 CAN 协议。该方案能消除当前的数据长度错误、越界复制、坏帧刷新在线状态、DMA 分片丢帧和陈旧数据继续下发问题，同时避免一次性改动全部裁判协议。

### 不采用：只修正 `0x0202` 长度

这种改法变更最小，但当前解析器仍不知道 UART 回调的实际字节数，仍可能越界读取，也不能可靠处理半包和坏帧后的重新同步，无法达到链路可靠性的目标。

### 不采用：全量升级裁判系统协议

全量升级会牵涉 UI、机器人交互和大量当前未使用命令，测试范围明显扩大，与本次功率链路目标无直接关系。

## 架构与职责

### UART BSP

`USARTInstance` 增加本次接收长度字段。`HAL_UARTEx_RxEventCallback()` 在调用模块回调前保存 `Size`，回调结束后按现有方式清理缓冲区并重新启动 DMA。

现有回调函数签名不变，避免影响遥控器、视觉等其他 USART 使用方。裁判模块通过自己的 `USARTInstance` 读取接收地址和实际长度。

### 裁判字节流解析器

新增与 HAL、FreeRTOS 无关的纯 C 解析单元。解析器维护一个有界线性缓存，接口接收任意长度的数据块并逐帧处理：

1. 丢弃 `0xA5` 之前的噪声；
2. 数据不足 5 字节时保留并等待下一块；
3. 校验 5 字节帧头 CRC8；
4. 从字节 1、2 读取完整的 16 位小端数据段长度；
5. 拒绝超过解析缓存上限的声明长度；
6. 整帧未到齐时保留数据；
7. 整帧到齐后校验 CRC16；
8. 校验命令对应的载荷长度，再发布有效帧；
9. 遇到错误时至少前移一个字节并重新寻找 `0xA5`，不因单个坏帧丢失其后的好帧。

解析器不直接写全局 `referee_info_t`，而是通过有效帧回调把命令码、载荷和序号交给裁判模块，便于主机测试。

### 裁判功率状态

裁判模块在收到有效帧后更新：

- `0x0201`：底盘功率上限、底盘输出允许位、接收时刻；
- `0x0202`：底盘缓冲能量、接收时刻；
- 有效帧计数、CRC/长度拒绝计数和丢失字节计数，供上板诊断使用。

两个关键命令都以 10 Hz 发送。任一命令超过 300 ms 没有收到有效更新，即认为功率快照无效。普通 UART 空闲中断、未知命令和 CRC 错误帧不能刷新关键数据时间，也不能令无效状态重新上线。

裁判模块提供只读功率快照接口。接口在短临界区内一次性复制以下数据，避免 UART 中断更新结构体时底盘任务读到撕裂值：

```c
typedef struct
{
    bool valid;
    bool chassis_output_enabled;
    uint16_t chassis_power_limit_w;
    uint16_t buffer_energy_j;
} RefereePowerSnapshot_s;
```

查询接口以当前毫秒时刻判断两个命令的 300 ms 新鲜度，并返回本次调用的一致快照。底盘应用不再直接读取裁判模块内部的功率结构体。

### 底盘与超级电容下发

`ChassisTask()` 继续以当前 5 ms 周期调用功率更新逻辑。每周期只读取一次裁判功率快照，并由同一份快照生成超级电容指令和底盘功率预算，避免两个消费者看到不同周期的数据。

有效快照下：

- `referee_power_limit_w` 原样写入 `0x061`；
- `buffer_energy_j` 原样写入 `0x061`；
- 只有裁判允许底盘输出、底盘不在零力模式且功率上限大于 0 时，`enable_dcdc` 才为真；
- 底盘基础预算使用同一裁判功率上限，再按现有超级电容状态与能量算法计算增补。

无效或超时快照下：

- 正式配置发送 `enable_dcdc = false`、功率上限 `0`、缓冲能量 `0`；
- 底盘功率预算进入现有失效安全路径，不使用最后一次有效裁判数据；
- 不因超级电容仍在线而恢复 DCDC 使能。

`CHASSIS_POWER_BENCH_TEST` 作为无裁判系统的显式台架调试入口保留，但仓库默认值改回 `0`。只有开发者主动编译为 `1` 时，才允许使用 `CHASSIS_POWER_BENCH_LIMIT_W`；台架路径仍不会伪造裁判系统缓冲能量。

## 错误处理

- 空指针、零长度输入和超过缓存容量的数据块安全返回；
- 缓存被无法完成的异常长度占据时，丢弃异常帧头并继续搜索下一帧；
- CRC8、CRC16 或命令载荷长度错误时，不更新业务数据；
- UART 守护进程只由通过 CRC 的有效裁判帧刷新；
- 裁判 UART 丢失回调继续负责重启 DMA，同时使关键功率数据自然在 300 ms 后失效；
- 超时判断使用无符号毫秒差值，允许系统 tick 回绕；
- 超级电容 CAN 发送失败不改变裁判快照，沿用现有 CAN 返回值和诊断方式；
- 本次不把临时通信错误升级为电机模块级永久故障。

## 主机测试

新增纯 C 主机测试，至少覆盖：

- 单个完整 `0x0201` 帧正确解析功率上限和底盘输出允许位；
- 单个完整 14 字节 `0x0202` 帧正确解析字节偏移 8 的缓冲能量；
- 数据段长度按 16 位小端读取；
- 一次输入多个完整帧；
- 一个完整帧被拆成多次输入；
- 帧前噪声和坏帧之后仍能解析后续好帧；
- CRC8、CRC16、声明长度和命令载荷长度错误不会更新功率状态；
- 仅收到 `0x0201` 或仅收到 `0x0202` 时快照无效；
- 两个关键帧均新鲜时快照有效；
- 任一关键帧超过 300 ms 后快照失效，tick 回绕时判断正确；
- 无效快照生成关闭 DCDC 且功率、缓冲均为零的指令；
- 有效快照正确生成现有 `0x061` 字节序列；
- 显式台架模式与正式失效安全配置互不混用。

测试只验证协议和控制逻辑，不替代 UART 接线、DMA 中断、CAN 总线和超级电容硬件联调。

## 固件与上板验证

自动验证包括：

- 运行新增裁判链路主机测试；
- 运行现有超级电容协议、功率预算和功率模型测试；
- 使用仓库现有 ARM 工具链完成一次干净固件构建；
- 确认构建无新增告警。

上板联调按以下顺序确认：

1. 裁判系统连接后，C 板持续得到 `0x0201`、`0x0202` 有效计数；
2. 抓取 C 板 `0x061`，确认功率上限和缓冲能量与裁判系统一致；
3. 拔掉裁判串口，300 ms 后确认 `0x061` 变为关闭 DCDC、功率和缓冲清零；
4. 恢复裁判串口，两个关键命令均重新有效后确认链路自动恢复；
5. 确认超级电容 `0x051` 状态接收与现有底盘电机 CAN 通信无回归。

## 完成标准

- 2026 协议下的 `0x0201`、`0x0202` 可正确解析；
- 半包、合包、噪声和 CRC 错误不会产生错误功率命令；
- 任一关键数据超过 300 ms 后，正式配置不再使用陈旧值；
- C 板到超级电容的现有 CAN 协议完全兼容；
- 所有相关主机测试通过，ARM 固件构建通过；
- 上板断连与恢复检查符合设计行为。
