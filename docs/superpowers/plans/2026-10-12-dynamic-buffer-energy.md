# 动态缓冲功率与电容双闭环实现计划

**目标：** 通过宏切换无电容直供和 F334 电容模式。无电容时，80 W 裁判限额下允许有缓冲支撑的约 120～140 W 加速；电容模式分别闭环输入取电和底盘负载功率。

**架构：** 扩展纯算法 `ChassisPowerBudgetUpdate`，保留未启用缓冲控制时的原接口行为。F407 给出动态输入目标，F334 执行输入功率闭环；F407 的已有功率外环跟随动态负载目标。原始裁判限额和缓冲继续透传，独立字段传输入目标。

**技术：** C11 / STM32F407、C++14 / STM32F334、CAN 8 字节帧、GCC 主机测试及 ARM GNU 构建。

**执行约束：** 用户已要求代码实现，按当前聊天直接执行。现有六个未提交文件的原改动须保留，Git 提交只包含本次增量；两端固件分别提交，不刷写硬件。当前默认无电容。不得将电容负载功率当成输入功率，不得将台架固定功率伪装成有效缓冲。

## 2. 双端通信与输入闭环

涉及 F407 `super_cap_protocol.*`、`super_cap.*` 及测试；F334 `Communication.cpp`、`PowerManager.*` 和纯协议策略头文件及其主机测试。

- [x] 先写协议测试：原始 80 W 字段保持原样；新增独立 110 W 目标；禁用指令清扩展；输入反馈解码拒绝坏版本/非有限值，单独计时。
- [x] `0x061` 字节 5～6 为小端输入功率目标，字节 7 为扩展标识 `0xA5`；没有标识时保留旧能量控制。
- [x] 新反馈 `0x052` 字节 0～3 为输入功率 float，4～5 为实际执行的输入目标 uint16，6 为版本 1，7 的 bit0 表示扩展策略生效。旧 `0x051` 保留布局。先通过输入反馈确认新固件，再允许缓冲增量。
- [x] F334 收到合法扩展目标后使用现有 `pidPowerReferee` 闭环输入，绕过固定 50 J 能量 PID；目标同时受原始限额及剩余缓冲约束。独立指令看门狗失效后关闭 DCDC，不能伪造满缓冲。
- [x] 输入和负载帧各自检查新鲜度，不允许一侧正常掩盖另一侧失联；输入反馈不刷新负载状态看门狗。
- [x] 主机验证帧布局、边界与状态失效；F334 完整构建。
