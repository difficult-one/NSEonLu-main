# 连续缓冲能量估算与渐变恢复

## 范围和目标

实现已确认的两项改进：用实测输入功率连续更新裁判缓冲能量估算；根据能量缺口调整恢复期间的输入预算。直供模式使用底盘功率计，电容模式使用 F334 的输入功率反馈。现有功率外环、最终硬上限、输出许可和双端 CAN 协议保持原职责。

这属于状态估算和提前预算调整，具有前馈作用；实测功率闭环仍负责控制真实功率。估算器本身不保证真实负载跟随预算，也不替代功率保护。

## 方案选择

采用带保守余量的确定性积分。直接把当前实测功率乘以整段帧龄会把最新功率误用于过去的高负载；连续积分只处理两次调用之间的区间。完整滤波观测器需要额外辨识结算时刻和噪声模型，本次使用可单独验证的保守下限。

### 新帧锚定和帧间积分

`ChassisPowerBudgetInput_s` 新增 `buffer_tick_ms`，由 `RefereePowerSnapshot_s.buffer_tick_ms` 传入。时间戳区分新样本；相同焦耳读数的新帧仍须重新锚定，同一帧的重复调用不能重置估算。时间戳的前后顺序按 uint32 回绕判断。

新有效帧的初始下限沿用原安全预留：

```text
worst_excess = max(max_boost, max(0, P_input_now) - P_ref_now)
E_lower = max(0, E_ref - energy_margin
                  - (worst_excess + power_margin) * (settlement_delay + frame_age))
```

相邻观测的实际时间间隔为 `uint32(本帧时间戳-上帧时间戳)/1000 + 本帧龄 - 上帧龄`；同一帧内简化为帧龄之差。帧间积分只处理同一裁判样本，跨帧用新样本锚定，但连续反馈确认和恢复计时在帧边界两侧使用同一时间规则。区间内采用相邻两次输入功率的较大非负值、裁判限额的较小值，保守处理升降功率和限额切换：

```text
dE/dt = min(P_ref_previous, P_ref_now)
        - max(0, P_input_previous, P_input_now) - power_margin
```

下限限制在 `0..max_energy-energy_margin`。负输入功率按 0 处理，不凭负功率推测裁判系统认可再生能量。

当前或前一次功率反馈无效、或观测间隔超过 20 ms 时，同帧区间按至少 `max_boost+power_margin` 的耗能速率扣减；若可见输入超额更大，使用较大值。该周期撤销积极增补，新裁判帧也不能跳过确认；下一段连续有效反馈才恢复。首次初始化可以从新鲜输入和保守锚点开始。非法缓冲或时间倒退使当前估算失效，重新取得有效数据后保守锚定。关闭缓冲功能或调用 Reset 清除观测器状态。

裁判结算相位、功率计误差和采样间未观测尖峰仍存在不确定性，因此保留原 0.1 s、3 J、5 W 预留。本次不会声称这些初值已由实机证明。

### 渐变恢复

恢复条件和 15/30 J 滞回、100 ms 退出确认保持不变。确认累计实际观测时间；重复的同一时刻观测不推进计时。新增目标恢复时间 `recovery_target_time_s=1.0`，原 `recovery_power_w=20` 改为最大减让能力：

```text
reduction = clamp((recovery_exit - E_lower) / recovery_target_time, 0, 20 W)
input_budget_goal = max(0, P_ref - reduction)
```

当下限或预测值达到 5 J 硬底座时，立即使用全部 20 W 减让能力。预算下降立即执行，恢复上升继续使用原 600 W/s 限速。增加 `recovery_reduction_w` 输出供断点检查，不修改现有 RTT CSV。

电容模式恢复期间降低的是输入取电目标；健康电容仍可辅助负载，负载目标继续受板端总能力约束。

## 验证

主机用例覆盖真实帧时间戳、低/高输入功率积分、重复样本、新帧校正、回绕、旧帧拒绝、跨帧反馈缺失/恢复和长间隔、负功率和能量边界。恢复用例覆盖连续力度、重复时刻不能累计确认、最大减让、低限额、硬底座、预测越界、滞回和上升限速。直供和电容算法仿真使用独立物理能量积分，每周期检查估算下限不高于同一时刻物理能量，验证功率响应延迟下的安全下界与恢复。

运行动态缓冲预算、旧电容预算、裁判与流解析、功率外环、瞬态和最终功率上限测试；构建默认直供、关闭缓冲策略和电容模式固件。本机 ARM 工具链已确认需要在沙箱外运行。实机刷写和参数辨识另行验收。

实机验收先记录裁判更新间隔和丢帧分布，再将实测输入功率积分与裁判缓冲变化对齐以辨识结算延迟。接收时间戳只能说明帧到达时刻，不能直接证明裁判结算时刻。测清时序和计量误差后，才评估估算带来的响应收益并调整 0.1 s、3 J、5 W 和 1 s 等参数。
