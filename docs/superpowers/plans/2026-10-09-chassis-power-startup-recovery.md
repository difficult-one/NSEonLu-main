# 底盘启动保护与快速恢复实施计划

目标：实现 2026-10-09 设计的完整第一阶段，默认观察；分支模型等待新的标定数据。

## 约束

- 保留既有模型、速度 PID、基础分配、超级电容预算及用户未提交的 40 W / 25 Hz / 26 列设置。
- `CHASSIS_POWER_CONTROL_STAGE=0/1/2/3` 分别为观察、快恢复、启动保护、完整慢环；默认 0。
- `CHASSIS_POWER_CAPTURE_ENABLE` 默认 0，诊断固件置 1；新增静态 RAM 总量不得超过 16 KiB。
- 电机任务独占瞬态状态；纯算法不得调用 HAL、CAN、日志或分配内存。

## 实施与提交

- [x] 诊断基线：原子控制/反馈快照、最终整数命令诊断、500 Hz 启动记录、t90、CRC 排空及 CSV 工具。
- [x] 快恢复：独立负修正、两份新鲜样本与 10 ms 释放确认、60 W/s 释放、慢积分隔离。
- [x] 启动保护：30 ms / 1.30 B / 能量额度、8 ms 转速预测、非单调可行区间、增长兜底及异常降级。
- [x] 慢环完善：RUN 稳定 100 ms 与驱动学习门槛、连续死区、独立回算、低需求衰减及恢复规则。

## 验证

每步先补行为测试并运行失败，再实现和回归；每步独立本地提交，仅提交本次改动。
完整构建功率计开启/关闭、普通/诊断及四个阶段，使用独立目录，比较 map 和静态 RAM。
上板验收遵循设计文档：分别记录架空/落地、20/30/40 W 和运动方向的 t90、峰值、超限时间/能量、恢复、稳态误差及任务耗时/栈余量。
主机验证不替代上板对照。
