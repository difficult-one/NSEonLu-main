# 底盘普通行驶、自转与冲刺的电容使用方案

日期：2026-10-10。状态：具体设计草案；本次只提交方案，不修改控制代码。

2026-10-11 修订：用户目前未接图传、不能使用键鼠，已确认暂不需要遥控器发射；增加负向拨轮冲刺的遥控器调试方案。

2026-10-12 修正：用户明确当前未接超级电容，优先实现[底盘动态缓冲功率与超级电容双闭环](2026-10-12-dynamic-buffer-energy-design.md)，通过宏切换直供/电容模式。本文继续作为后续运动场景草案，不是当前功能的启用前提；新实现不依赖Shift/拨轮冲刺，普通加速即可消耗缓冲。本文低缓冲直接禁止所有电容助力的规定由新方案取代，安全系数以统一配置为准。

## 1. 已确认的运动目标

| 场景 | 运动目标 | 电容使用 |
| --- | --- | --- |
| 普通行驶 | 跟随操作手给定的目标速度 | 优先保留能量，有余量时自动充电 |
| 自转 | 在可用预算内尽量快 | 自动补电，同时预留平移机动余量 |
| 按住冲刺键 | 优先快速加速 | 允许更积极地消耗电容 |
| 自转时按住冲刺键并给出平移输入 | 优先平移加速 | 增大助力预算，同时降低自转目标 |

用户已确认组合操作采用“优先平移加速，自转让出功率”。两种输入统一生成 `sprint_request`：键鼠用 **Shift 按住状态**，当前遥控器调试用 **负向拨轮保持状态**；释放输入即退出。后文“冲刺请求”和“释放输入”均适用于这两种操作，场景预算与电量保护共用。

第一版冲刺沿用现有 `vx/vy` 目标值，通过更大的可用功率改善受限时的加速。目标速度已到达时，不为了消耗电容继续增加平移速度。提高冲刺终速度需要另外设计速度倍率，不包含在本次方案内。

### 1.1 当前拟采用的遥控器调试版

遥控器接收链路与图传/键鼠输入分开使用；本方案从现有 `rc_data[TEMP].rc` 读取拨杆、摇杆和拨轮，不依赖键鼠按键数据。操作映射如下：

| 操作 | 作用 |
| --- | --- |
| 左侧拨杆下位 | 进入现有遥控器控制模式 |
| 右侧拨杆中位 | 普通行驶，右摇杆控制平移 |
| 右侧拨杆下位 | 自转，右摇杆仍可控制平移 |
| 负向拨轮保持在冲刺区，并推动右摇杆 | 请求平移冲刺；自转时同时降低自转目标 |
| 拨轮回中位 | 退出冲刺，返回普通/自转策略 |
| 正向拨轮 `dial > 300` | 保留现有急停操作，禁止冲刺 |
| 右侧拨杆上位 | 保留现有恢复入口，不用于冲刺；恢复前先将拨轮回中位 |

代码现有注释把负向称为“向上拨”，正向称为“向下拨”；正式操作说明以遥测确认的 `dial` 正负为准。

冲刺输入初值：`dial <= -500` 时置请求，`dial >= -350` 时清请求，中间区间保持上一次请求状态，避免门槛附近反复切换。进入遥控器模式、上电、急停恢复、输入离线恢复或本次冲刺因保护被锁定后，都必须先收到在线遥控器的 `abs(dial) <= 100` 中位状态持续 200 ms，再允许负向拨轮申请。不能用离线后自动清零的缓存解除锁定。

只在左拨杆下位、右拨杆中位/下位、遥控器在线且机器人允许输出时接受拨轮冲刺。右摇杆没有非零平移请求时，负向拨轮不单独增加自转预算；平移请求门槛和功率策略见第 4.3 节。

启用此遥控器调试版时，负向拨轮不再承担摩擦轮和拨弹控制：每周期明确设置 `shoot_mode=SHOOT_OFF`、`friction_mode=FRICTION_OFF`、`load_mode=LOAD_STOP`，并保证它们不被后续恢复分支覆盖。该模式下不能因冲刺拨轮动作启动发射。

这项映射需要新增控制代码。当前固件的负向拨轮仍控制摩擦轮和发射，尚不能直接按上述操作使用冲刺。

## 2. 推荐实现与现状

推荐采用“场景预算 + 自转目标调节”。扩展现有 `chassis_power_budget` 处理场景、电量门槛、增补和切换；现有 `chassis_spin` 处理自转速度；既有速度 PID、四轮功率模型和瞬态保护继续执行最后的限流。

另外两种思路的取舍：

- 手动开关 DCDC：操作简单，但关闭后会影响充电，无法自然表达普通行驶、自转和冲刺的不同预算。
- 分解平移和旋转的电流并分别分配功率：可以实现更严格的力矩优先级，但需要新的分配器、制动处理及实车标定，改动明显更大。

目前代码已具备的基础：

- F407 自动向 F334 发送 DCDC 使能、裁判原始功率上限及原始缓冲能量；有效数据、输出权限和非 `CHASSIS_ZERO_FORCE` 是使能条件。
- 电容板自行控制充放电。F407 协议没有独立的“开始放电”或“冲刺”指令。
- 当前所有运动场景共用一套电容增补：电量 10% 以下不增补、30% 以上全增补、最多增加 100 W、上升 200 W/s。尚未区分普通、自转和冲刺。
- `MouseKeySet()` 已有 Shift 处理位置，但未实现；`Chassis_Ctrl_Cmd_s` 尚无冲刺字段。
- 上一次提交已经提供 `CHASSIS_SPIN_ADAPTIVE_ENABLE`。宏为 0 时自转目标为 4000；宏为 1 时按实测功率调节。

因此，“电容自动开启”与“保持冲刺输入时更积极用电”可以同时成立。普通行驶保持 DCDC 自动使能，只收紧底盘负载预算，让控制板利用实际余量充电。

## 3. 数据含义与预算公式

以下量必须分开记录：

| 量 | 含义 |
| --- | --- |
| `P_ref` | 有效裁判系统给出的原始底盘功率上限 |
| `P_board` | F334 上报的底盘总可用功率，已经包含输入侧贡献 |
| `E_cap` | 电容板上报的能量比例，范围 0～1 |
| `E_buffer` | 裁判缓冲能量，单位 J；与电容能量分别判断 |
| `B_nominal` | 场景策略给电机控制器的名义预算 |
| `P_limit` | 名义预算乘现有 0.95 安全系数后的控制目标 |
| `P_seek` | 自转调节器追踪的总负载功率目标，另扣机动余量 |

F334 状态正常且输出已使能时，取 `B_base = min(P_ref, P_board)`，避免忽略控制板上报的更低总能力。电容离线、禁用或故障时，按现有链路回退到有效基础预算；硬件停机和机器人输出权限仍优先执行。

```text
H_hw = max(0, P_board - P_ref)
H_mode = min(H_hw, 本场景增补上限, 全局增补上限 100 W)
H_allowed = 助力条件有效 ? f_energy × H_mode : 0
B_goal = B_base + H_allowed
B_nominal = 对 B_goal 执行上升限速，下降立即生效
P_limit = 0.95 × B_nominal
```

`P_board` 是总预算，不能写成 `P_ref + P_board`。`P_limit` 不再乘第二次安全系数。功率模型纠偏后的预算只用于补偿模型偏差，不用来反推更大的物理目标。

普通行驶不额外扣除固定充电功率，先使用基础预算。实际需求低于输入侧供电能力时，F334 自动充电；是否充电及充电速度取决于负载、转换损耗和控制板的输入限制。0.95 是现有功率安全裕量，不能视为保证的充电功率。

## 4. 三种场景的具体策略

### 4.1 普通行驶

- `H_allowed = 0`，只使用基础预算。
- `vx/vy` 和跟随云台模式的旋转目标沿用现有驾驶输入；到达目标后维持跟踪，不追着功率上限增加目标速度。
- 负载较小时由 F334 自动补充电容能量。电容接近满电时仍不强迫电机消耗功率。
- 功率外环的正向修正仅在模型已限流、有足够驱动需求且反馈有效时允许学习；保留超功率负向修正、制动和失效保护。

最后一项需要覆盖旧阶段 0/1/2 的普通行驶路径，避免“负载很轻，但功率外环仍累积正向修正”。这是新策略启用后的行为，宏关闭时保留原行为。

### 4.2 自转

- 自动允许较小的持续增补，初值最多 **40 W**。
- 电量降到 **20%** 时移除自转增补；回到 **25%** 并持续 200 ms 后重新允许。允许后，20%～50% 之间线性增加，50% 以上允许本场景全增补。
- `f_energy = clamp((E_cap - 0.20) / 0.30, 0, 1)`；首次进入及停止增补后，未通过重新允许条件时取 0。
- 自转调节器使用 `P_seek = 0.85 × P_limit`，保留 **15% 的总功率目标余量**。实测功率已经包含平移，不能再把平移功率额外加到目标上。
- 沿用自转目标初值 4000、范围 1000～6000、增速上限 400 命令单位/s、正常降速上限 2000 命令单位/s及现有反馈门槛。
- 有平移需求导致功率增加时，自转调节器减少 `wz`。刚开始跟踪、制动、限流或反馈不新鲜时，禁止自转继续增速。

按功率追踪并维持 15% 余量要求同时开启自转自适应宏。仅开启新场景策略而关闭自转自适应时，仍使用固定目标 4000，不能保证该功率余量；这个组合用于分别比较预算策略和自转纠偏的效果。

15% 是应对突然机动的功率余量，不能直接解释成“已经分配了 15% 的平移力矩”。四轮共享限流器，真实机动效果需要验证。也不能保证自转一直维持增补：电容能量下降后应主动减速、回到基础预算。

`wz=4000/6000` 是本项目现有控制命令数值，不是电机 rpm，也不是已经标定的底盘实际转速。6000 仍是待实车验证的初始上限。

### 4.3 保持冲刺输入

进入条件：有效驾驶命令、有效输出权限、非零平移请求、电容和功率反馈正常、电量至少 **25%**、裁判缓冲能量已恢复到允许助力的范围。

- 平移请求以 `sqrt(vx² + vy²) > 30` 判断，30 使用当前命令单位。冲刺输入有效但没有平移请求时，保持普通或自转策略。
- 冲刺最多允许 **100 W** 增补；`f_energy = clamp((E_cap - 0.10) / 0.20, 0, 1)`，30% 以上允许全增补。
- 预算上升限速初值 **1000 W/s**。从无增补到增加 100 W，理论爬升时间约 100 ms；控制板及电机保护仍可限制实际输出。
- 电量降到 **10% 或以下**、缓冲能量降到助力下界或以下，或出现助力反馈故障时，立即移除增补并锁住本次冲刺。能量恢复后，需先释放冲刺输入再重新申请：键鼠松开 Shift；遥控器将拨轮回中位持续 200 ms，避免持续保持输入时反复开启。
- 释放冲刺输入或平移请求回到死区时，下周期退出；切回基础/自转预算，下降立即生效，既有瞬态保护处理电流变化。

第一版不加固定“几秒后退出”的定时器。可持续时间由实际电量、负载和门槛决定；低电量锁定及释放输入后重申请是确定的退出机制。

## 5. 自转和冲刺的组合操作

满足冲刺进入条件后，自转模式继续保留，具体动作如下：

1. 预算切到冲刺档，优先满足当前平移目标的加速需求。
2. 立即禁止自转正向增速；自转目标上限收紧到 **1000**，沿原旋转方向以最多 **10000 命令单位/s** 向这个值下降。
3. 如果进入时目标已经低于 1000，不因冲刺把它向上抬高。功率超限时允许继续采用正常自转调节的减速动作。
4. 冲刺输入仍有效且有平移输入时，维持较低自转目标，不因冲刺预算变大再次压榨旋转速度。
5. 释放冲刺输入、无平移请求或冲刺被锁定后，返回自转档；从当前目标接续，等待反馈稳定 200 ms，再按正常增速率恢复。

关闭自转自适应但启用新策略时，也执行组合让速和受限恢复；恢复终点为固定目标 4000，恢复上升限速仍为 400 命令单位/s。低电量或故障仍执行对应的预算保护。

平移目标不打折。降低自转目标发生在四轮速度解算之前，不在四轮电流分配以后粗暴扣电流；降速引起的制动仍由现有保护处理。

这个方案实现的是**运动目标层的平移优先**。当前轮级分配器没有显式分解平移和旋转力矩，所以不声称能够严格保证每个瞬间的平移功率占比。验收必须看实际平移响应；若让速后仍明显抢功率，再单独设计力矩分配器。

## 6. 进入、退出和故障优先级

决策顺序：

```text
急停 / ZERO_FORCE / 无有效基础预算 / 输出不允许
  → 禁止输出，清空冲刺请求和自转恢复状态；冲刺等待有效释放输入
否则：冲刺请求有效 + 非零平移请求 + 助力条件有效 + 冲刺允许
  → SPRINT；若同时自转，则让速
否则：CHASSIS_ROTATE
  → SPIN
否则
  → NORMAL

场景选出后，再按该场景的电量/缓冲/反馈条件决定是否允许增补。
助力条件无效时，H_allowed = 0，并执行既有故障降级。
```

“冲刺锁定”只禁止本次冲刺增补，不阻止后来满足条件的普通或自转策略。因电量 10% 或缓冲过低锁定时，自转增补通常也不满足自身门槛；因输入释放而正常退出时不设置故障锁定。

助力要求电容状态年龄不超过 **20 ms**。现有 200 ms 电容离线看门狗保留；新增更短门槛只影响增补，防止把 200 ms 的旧总预算用于积极放电。自转增速继续要求功率计年龄不超过 20 ms、控制及电机状态年龄不超过 5 ms。

功率计失效时，新策略立即取消电容增补、自转增速和冲刺申请。使用有效基础预算及模型限流降级，不自动切换到未经核对测量位置的电容板功率值。反馈恢复后重新通过稳定和冲刺进入条件。

自转已降到低于 4000 后发生测量失效，回退目标采用 `min(当前自转目标, 4000)`，避免失效时反而跳回更高速度；现有宏关闭路径保持原样。急停后再次进入自转则仍从正常初始值 4000 开始，由输出限流保护起步。

裁判缓冲助力下界初值 **25 J**，恢复门槛 **30 J**，恢复须持续 200 ms。`E_buffer <= 25 J` 立即禁止自转及冲刺增补；首次启动及禁止后，必须达到 `E_buffer >= 30 J` 并稳定 200 ms 才允许助力。25 J 对应当前本地 F334 配置 `ENERGY_BUFFER=50 J` 的一半；它是本方案的调试参数，不能当作比赛规则阈值。F334 已有输入侧能量保护仍继续工作。

本次冲刺因反馈故障锁定时，故障解除也必须释放输入重新申请。输入链路离线时请求清零并进入 ZERO_FORCE；实现时明确检查 `RemoteControlIsOnline()`，不能假定遥控器缓存清零已经停止底盘。恢复时若 Shift 仍按住或拨轮仍在负向冲刺区，应等待有效释放输入，不接受旧状态继续冲刺。

## 7. 通信、宏和代码落点

### 通信

- 在 `Chassis_Ctrl_Cmd_s` 增加 `uint8_t sprint_request`，每次组包先置 0；在线键鼠明确按住 Shift，或启用遥控器调试版且满足拨轮申请条件时赋 1。
- 未启用拨轮映射的遥控器模式、非驾驶输入模式、急停和无效输入每周期明确清零，避免残留位。
- 单板消息中心与双板 CANComm 同时使用新的结构长度；双板固件需同步更新，不能混用新旧布局。
- 底盘侧使用有效完整命令的接收时间，超过 30 ms 不再接受冲刺。CANComm 的在线状态也必须有效；不能因 `CANCommGet()` 还能返回缓存就继续接受旧的冲刺请求。
- 单板订阅成功、双板完整校验帧成功后才刷新接收时间。需要为 CANComm 提供可读取的最后完整帧时间；轮询旧缓存、残缺帧和 CRC 失败不刷新。
- 为电容状态查询补充同一快照的最后有效帧时间，保证 20 ms 助力门槛可判断；不把内部临时诊断变量当作应用长期接口。
- F407→F334 的 `0x061` 和 F334→F407 的 `0x051` 布局保持当前协议。指令持续携带真实裁判原始功率上限和缓冲能量，不能传场景增补或打折后的值。
- 零速度且非 ZERO_FORCE 时允许自动充电；急停进入 ZERO_FORCE 后按照现有规则关闭 DCDC。

### 宏

新增 `CHASSIS_ENERGY_POLICY_ENABLE`，默认 **0**，独立配置放到 `modules/algorithm/chassis_energy_config.h`，支持 Make/CMake 编译参数覆盖。既有自转宏继续保留。

另新增 `CHASSIS_RC_SPRINT_ENABLE`，默认 **0**。仅当它与 `CHASSIS_ENERGY_POLICY_ENABLE` 同时为 1 时，启用负向拨轮冲刺及该遥控器模式的发射关闭策略；否则保持原遥控器拨轮映射。键鼠 Shift 请求仍由场景策略宏控制。

用户当前遥控器调试固件拟设 `CHASSIS_ENERGY_POLICY_ENABLE=1`、`CHASSIS_RC_SPRINT_ENABLE=1`，需要自转纠偏时再设置 `CHASSIS_SPIN_ADAPTIVE_ENABLE=1`。这些宏是后续实现配置，当前尚未新增前两个宏。

| 新策略宏 | 自转自适应宏 | 对比行为 |
| ---: | ---: | --- |
| 0 | 0 | 当前统一电容预算 + 固定自转 4000 |
| 0 | 1 | 当前统一电容预算 + 已实现的自转自适应 |
| 1 | 0 | 三场景电容预算 + 固定自转；组合冲刺时仍让速 |
| 1 | 1 | 三场景电容预算 + 自转纠偏、余量和冲刺让速 |

新策略宏为 0 时不执行场景选择、普通行驶新增学习门槛、冲刺增补及让速。新增命令字段仍需两端布局一致，宏不能解决新旧双板固件不兼容。

### 落点与职责

| 文件/模块 | 后续实现职责 |
| --- | --- |
| `application/cmd/robot_cmd.c` | Shift/拨轮统一请求、拨轮滞回与中位解锁、遥控器调试发射关闭、输入切换及请求清零 |
| `application/robot_def.h` | 冲刺字段，双板数据布局 |
| `modules/can_comm/can_comm.*` | 最后完整有效帧的时间查询 |
| `modules/super_cap/super_cap.*` | 一致的状态与有效帧时间查询，协议载荷不变 |
| `modules/algorithm/chassis_power_budget.*` | 场景状态、电量/缓冲滞回、增补公式和预算限速；保持纯算法 |
| `modules/algorithm/chassis_energy_config.h` | 功能宏和场景参数 |
| `modules/algorithm/chassis_spin.*` | 独立功率追踪目标、冲刺目标上限、恢复和失效规则 |
| `application/chassis/chassis.c` | 数据有效性、场景路由、运动目标让速及统一控制快照 |
| `modules/motor/DJImotor/dji_motor.c` | 接收预算和诊断；现有速度 PID/最终保护继续负责电流 |
| `modules/telemetry` | 发布可观察的场景和退出原因 |
| `Makefile` / `CMakeLists.txt` | 新宏透传及已有算法测试接入 |

不再叠加一套电容能量 PID。场景策略只给出允许的预算，F334 负责输入侧供电与电容电压控制，F407 负责负载侧运动及功率控制。

场景预算、自转追踪目标、四轮目标和保护参数必须来自同一次 5 ms 控制决策，统一发布给电机任务，避免切换周期混用前后两种预算。自转正向学习保持与当前控制阶段的保护门槛一致，功率超限和制动规则不被场景分支跳过。

保护能力遵循 `CHASSIS_POWER_CONTROL_STAGE`：阶段 0 的新增瞬态算法只计算诊断，不能声称已执行完整预测保护。真实助力的首次验证建议使用阶段 3；前后对比必须保持相同阶段。该建议不改变当前固件的阶段配置。

## 8. 初始参数汇总与数值例子

所有新增值都是第一轮台架参数，应通过数据修改，不是已验证的最优值。

| 参数 | 初值 |
| --- | ---: |
| 普通行驶额外增补 | 0 W |
| 自转增补上限 / 全局及冲刺增补上限 | 40 W / 100 W |
| 自转停止增补 / 重新允许 / 全增补电量 | 20% / 25% / 50% |
| 冲刺停止增补 / 进入 / 全增补电量 | 10% / 25% / 30% |
| 自转机动功率余量 | `P_limit` 的 15% |
| 自转预算上升 / 冲刺预算上升 | 200 W/s / 1000 W/s |
| 预算下降 | 下周期立即生效 |
| 冲刺期间自转目标上限 / 降速上限 | 1000 / 10000 命令单位/s |
| 无平移输入死区 | 30 命令单位 |
| 遥控拨轮申请 / 退出阈值 | `dial <= -500` / `dial >= -350` |
| 遥控拨轮解锁中位 / 稳定时间 | `abs(dial) <= 100` / 200 ms |
| 缓冲停止助力 / 恢复助力 | 25 J / 30 J |
| 稳定恢复时间 | 200 ms |

例如：`P_ref=60 W`、健康控制板报告 `P_board=200 W`、电量 60%、缓冲正常，且已完成预算上升。

| 场景 | 名义预算 | 最终功率目标 `P_limit` | 自转追踪目标 |
| --- | ---: | ---: | ---: |
| 普通行驶 | 60 W | 57 W | 无自转追踪 |
| 自转 | 100 W | 95 W | 80.75 W，另有 14.25 W 机动余量 |
| 冲刺 | 160 W | 152 W | 组合操作时优先收紧转速，不追满 152 W |

这表示允许输出到多少功率。普通行驶实际只需要 30 W 时仍按目标速度行驶；冲刺目标已跟上时也不会主动制造额外负载。

当前本地 F334 的比例按 `V_cap² / V_max²` 计算，尚未扣除最低工作电压对应的能量。20%/10% 等门槛指协议上报值；不能直接换算成“还可冲刺几秒”。持续时间需要电容量、可用电压范围、转换效率和实测耗电。

## 9. 可观察性和验收

遥测至少增加：场景 `NORMAL/SPIN/SPRINT`、输入来源 `NONE/KEYBOARD/RC_DIAL`、Shift/拨轮原始请求与接受状态、拨轮值及中位解锁状态、电容比例、裁判缓冲、板端总能力、允许增补、名义预算、最终功率目标、自转功率追踪目标、当前 `wz`、让速标志及退出/禁止原因。禁止原因使用固定枚举，包括输入过期、输出禁止、电容状态过期、功率计失效、低电量、低缓冲和等待释放输入。

实施后验证以下行为：

1. **正常行驶**：同一速度命令且负载不触发限流时，新策略不改变目标；有实测输入余量时电容能量应恢复，不要求所有移动负载都能充电。
2. **自转加速**：反馈稳定且低于 `P_seek` 时，目标可从 4000 增加；到达预算或速度上限后不继续积累；加平移时不再追着原旋转速度增长。
3. **平移余量**：自转稳定后施加相同平移阶跃，对比无余量版本，记录平移到达目标 90% 的时间、轨迹偏差及总功率峰值。预算余量存在还需同时确认真实响应改善。
4. **冲刺**：在起步确实受预算限制的相同载荷下，对比冲刺输入开关后的平移加速时间；分别覆盖拨轮和 Shift，目标值保持一致。电量充足但需求不足时不要求多消耗功率。
5. **组合操作**：确认预算增大时 `wz` 不跟着升高，按配置向低目标下降；释放冲刺输入后等待稳定再恢复。通过轮速逆运动学或外部测速提取平移响应，不能把最大单轮速度误差当作平移误差。
6. **临界值**：覆盖电量 10%/20%/25%/30%/50%、缓冲 25/30 J、门槛附近来回波动、保持冲刺输入耗尽及释放后重申请。
7. **故障**：覆盖裁判/电容/功率计/命令链路离线、旧帧、输出禁止、掉电重启和非法浮点数；失效后不残留增补和冲刺，也不因回退提高低速自转目标。
8. **预算边界**：覆盖 `P_board<P_ref`、无额外能力、输入功率下降、增补上限和不同更新周期；裁判原始数据始终不被场景预算替换。
9. **宏对比**：覆盖两个功能宏的四种组合，并检查功率阶段 0～3 的学习门槛、制动和保护；宏关闭时新增策略状态不改变原控制输出。
10. **遥控器输入**：覆盖 -500/-350 滞回、±100 中位解锁、非零平移条件、上电时拨轮已在冲刺区、离线清零不能解锁及恢复仍保持拨轮；从遥控器切到键鼠/其他输入模式时不能沿用拨轮请求。
11. **遥控器调试隔离**：两个相关宏同时启用时，负向拨轮任意幅度都不能开启摩擦轮或拨弹；正向 `dial > 300` 必须优先急停，右拨杆上位恢复不能覆盖发射关闭策略。两个宏任一关闭时检查原拨轮映射，明确记录该固件仍存在发射操作。

算法部分用确定性输入覆盖公式、滞回、恢复、超时和预算变化；适配层检查单板/双板构建及命令布局。实车对比使用相近初始电量、相同地面、载荷和命令，重点比较加速时间、真实自转速度、能量下降和保护介入次数。

上车前核对功率计位于包含电容供能的底盘负载侧。若测到的是裁判输入侧，不能用它追踪电机总功率。当前台架模式发送缓冲 0 J，新策略默认因此不启用助力；公式和场景测试可使用明确注入的有效快照，真实助力验证需提供正确数据及测量条件。

## 10. 实施顺序

后续按三个可独立验证的步骤推进：

1. 加入宏、统一 Shift/拨轮请求、遥控器调试发射关闭、完整帧时间和场景预算，先验证普通行驶保电及低电量降级。
2. 接入自转 15% 功率余量、组合让速和释放输入后的恢复，验证四轮解算前的目标变化及真实平移响应。
3. 扩展遥测，完成算法/构建验证和同工况实车对比，再根据数据调整 40/100 W 与电量门槛。

这次没有启用或写入上述控制策略，也没有进行助力上车测试。
