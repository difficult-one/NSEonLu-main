# 回调函数注册与接收机制

> 结合本项目（NSEonLu）CAN/USART 通信框架的源码分析

---

## 1. 核心概念

**回调函数设计的初衷**：为底层代码调用上层代码提供接口，当特定事件发生时完成触发。

> 正常调用方向是 **上层 → 底层**（Module 调用 BSP 的发送函数），但接收方向是反的——数据从硬件来，底层需要**反向通知上层**。回调函数就是实现这种"反向调用"的机制。

## 3. 分步解析（以 CAN 总线为例）

### 第 1 步：定义回调函数指针类型

`bsp_can.h:26` — 在 BSP 层的 CAN 实例结构体中定义了一个**函数指针**成员：

```c
typedef struct _
{
    CAN_HandleTypeDef *can_handle;    // CAN 句柄
    CAN_TxHeaderTypeDef txconf;       // 发送配置
    uint32_t tx_id;                   // 发送 ID
    uint32_t rx_id;                   // 接收 ID
    uint8_t tx_buff[8];              // 发送缓冲
    uint8_t rx_buff[8];              // 接收缓冲

    // ★ 回调函数指针 ★
    // BSP 层不关心这个函数具体做什么，只知道它的签名：
    //   参数: CANInstance* — 把实例自身传进去
    //   返回: void
    void (*can_module_callback)(struct _ *);

    void *id;  // 拥有此 CAN 实例的模块指针，用于回调时反查模块
} CANInstance;
```

> `can_module_callback` 只是一个**指针变量**，存的是函数的入口地址。BSP 层**不知道**也**不需要知道**这个函数具体做了什么——它只需要知道函数的签名（参数类型 + 返回值类型）。

### 第 2 步：Module 层实现回调函数

`modules/can_comm/can_comm.c:26` — can_comm 模块**自己实现**接收数据的解析逻辑：

```c
static void CANCommRxCallback(CANInstance *_instance)
{
    // 通过 id 反查到自己模块的实例（关键！）
    CANCommInstance *comm = (CANCommInstance *)_instance->id;

    // 1. 帧头检测
    if (_instance->rx_buff[0] == CAN_COMM_HEADER && comm->recv_state == 0)
    {
        if (_instance->rx_buff[1] == comm->recv_data_len)
            comm->recv_state = 1;   // 开始接收
        else
            return;
    }

    // 2. 组包（CAN 每帧最多 8 字节，长数据需要多帧拼接）
    if (comm->recv_state)
    {
        memcpy(comm->raw_recvbuf + comm->cur_recv_len,
               _instance->rx_buff, _instance->rx_len);
        comm->cur_recv_len += _instance->rx_len;

        // 3. 收完 → CRC 校验
        if (comm->cur_recv_len == comm->recv_buf_len)
        {
            if (comm->raw_recvbuf[comm->recv_buf_len - 1] == CAN_COMM_TAIL
                && crc8_check_pass())
            {
                memcpy(comm->unpacked_recv_data,
                       comm->raw_recvbuf + 2, comm->recv_data_len);
                comm->update_flag = 1;           // 标记有新数据
                DaemonReload(comm->comm_daemon); // 喂狗
            }
            CANCommResetRx(comm); // 重置状态机
        }
    }
}
```

`modules/motor/DJImotor/dji_motor.c:122` — DJI 电机模块也有自己的回调：

```c
static void DecodeDJIMotor(CANInstance *_instance)
{
    DJIMotorInstance *motor = (DJIMotorInstance *)_instance->id;
    DJI_Motor_Measure_s *measure = &motor->measure;

    DaemonReload(motor->daemon);

    measure->ecd = (_instance->rx_buff[0] << 8) | _instance->rx_buff[1];
    measure->speed_rpm = (_instance->rx_buff[2] << 8) | _instance->rx_buff[3];

}
```

> **关键**：回调函数的实现代码全在 Module 层，BSP 层完全不知道它们的存在。

### 第 3 步：注册回调（绑定）

`modules/can_comm/can_comm.c:80-95` — Module 初始化时，把自己的回调函数地址**传给 BSP 层**：

```c
CANCommInstance *CANCommInit(CANComm_Init_Config_s *comm_config)
{
    CANCommInstance *ins = (CANCommInstance *)malloc(sizeof(CANCommInstance));
    // ... 初始化各种字段 ...

    // ★ 注册回调的核心三步 ★
    comm_config->can_config.id = ins;                              // ① 告诉 BSP "我是谁"
    comm_config->can_config.can_module_callback = CANCommRxCallback; // ② 把函数地址传进去
    ins->can_ins = CANRegister(&comm_config->can_config);          // ③ 调用 BSP 的注册接口

    return ins;
}
```

`bsp/can/bsp_can.c:63-102` — BSP 层把回调函数指针**保存**到全局实例数组中：

```c
static CANInstance *can_instance[CAN_MX_REGISTER_CNT] = {NULL};
static uint8_t idx;  // 当前已注册的实例数量

CANInstance *CANRegister(CAN_Init_Config_s *config)
{
    // 第一次注册时自动初始化硬件
    if (!idx) CANServiceInit();

    // 安全检查：防止重复注册、ID 冲突
    // ...

    CANInstance *instance = (CANInstance *)malloc(sizeof(CANInstance));

    // ★ 把上层传来的配置保存下来 ★
    instance->can_module_callback = config->can_module_callback;  // 存回调
    instance->id = config->id;                                    // 存模块指针
    instance->can_handle = config->can_handle;
    instance->rx_id = config->rx_id;
    // ...

    CANAddFilter(instance);           // 配置硬件过滤器
    can_instance[idx++] = instance;   // 加入全局数组
    return instance;
}
```

### 第 4 步：中断触发 → 回调被调用

这是最关键的一步，展示了**底层如何调用上层**。

**4a. 硬件中断 → HAL 库回调**

`bsp/can/bsp_can.c:184-197` — HAL 库在 CAN 接收 FIFO 有数据时，调用 `__weak` 函数，我们重写它：

```c
// 重写 HAL 库的弱定义回调
void HAL_CAN_RxFifo0MsgPendingCallback(CAN_HandleTypeDef *hcan)
{
    CANFIFOxCallback(hcan, CAN_RX_FIFO0);
}

void HAL_CAN_RxFifo1MsgPendingCallback(CAN_HandleTypeDef *hcan)
{
    CANFIFOxCallback(hcan, CAN_RX_FIFO1);
}
```

**4b. 遍历匹配 + 调用上层回调**

`bsp/can/bsp_can.c:149-170` — 从硬件 FIFO 取出数据，遍历所有已注册实例，找到匹配的，**调用该模块的回调函数**：

```c
static void CANFIFOxCallback(CAN_HandleTypeDef *_hcan, uint32_t fifox)
{
    CAN_RxHeaderTypeDef rxconf;
    uint8_t can_rx_buff[8];

    // 只要 FIFO 里还有数据就继续取（可能一次中断积压了多帧）
    while (HAL_CAN_GetRxFifoFillLevel(_hcan, fifox))
    {
        HAL_CAN_GetRxMessage(_hcan, fifox, &rxconf, can_rx_buff);

        // 遍历所有已注册的 CAN 实例
        for (size_t i = 0; i < idx; ++i)
        {
            // 匹配条件：同一个 CAN 控制器 + 同一个接收 ID
            if (_hcan == can_instance[i]->can_handle
                && rxconf.StdId == can_instance[i]->rx_id)
            {
                // 拷贝数据到实例的接收缓冲
                can_instance[i]->rx_len = rxconf.DLC;
                memcpy(can_instance[i]->rx_buff, can_rx_buff, rxconf.DLC);

                // ★★★ 核心！调用上层模块注册的回调函数 ★★★
                if (can_instance[i]->can_module_callback != NULL)
                    can_instance[i]->can_module_callback(can_instance[i]);

                return;  // 找到对应实例，不必继续遍历
            }
        }
    }
}
```

## 4. USART 的同款机制

`bsp/usart/bsp_usart.c:102-115` — USART 也是一模一样的模式：

```c
void HAL_UARTEx_RxEventCallback(UART_HandleTypeDef *huart, uint16_t Size)
{
    for (uint8_t i = 0; i < idx; ++i)
    {
        if (huart == usart_instance[i]->usart_handle)
        {
            if (usart_instance[i]->module_callback != NULL)
            {
                usart_instance[i]->module_callback();  // ★ 调用上层回调 ★
                memset(usart_instance[i]->recv_buff, 0, Size);
            }
            // 重新启动 DMA 接收（循环接收）
            HAL_UARTEx_ReceiveToIdle_DMA(/* ... */);
            return;
        }
    }
}
```

## 6. 关键设计要点

| 设计点 | 说明 |
|--------|------|
| **函数指针** | BSP 层只存地址，不关心实现 |
| **void\* id** | 回调时反查模块实例（因为 C 没有闭包/this 指针） |
| **注册即初始化** | 第一个模块注册时自动初始化硬件，懒加载 |
| **实例数组** | 一个 CAN 总线可挂多个模块，共享中断服务 |
| **NULL 检查** | 调用前判断回调不为空，防止野指针 |
| **Hash 匹配** | 用 `(hcan, rx_id)` 二元组匹配，O(n) 但 n 很小 |

---

## 7. 与 Hook 函数的关系

> **Hook = 钩子 = 预留的"挂载点"**
> **回调函数 = 挂在钩子上的具体逻辑**

- `can_module_callback` 字段就是那个**钩子**（Hook Point）
- `CANCommRxCallback` / `DecodeDJIMotor` 就是**挂在钩子上的函数**
- 中断发生时，BSP "拉一下钩子"，所有挂在上面（已注册）的逻辑就被触发

你可以自行搜索 "Hook 函数"、"钩子函数" 来进一步理解这个概念。
